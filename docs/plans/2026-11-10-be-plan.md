# Plan backend: Restaurant Manager

> Trạng thái: **đã dựng khung Spring Boot** (giai đoạn 0). Các giai đoạn 1–9 chưa làm.
> Nguồn nghiệp vụ: `restaurant-manager-fe/docs/superpowers/specs/2026-11-08-restaurant-system-design.md` (gọi tắt **spec**) và `restaurant-manager-fe/docs/superpowers/plans/2026-11-09-fe-redesign.md` mục 2 (gọi tắt **plan FE**). Chỗ nào plan FE sửa spec thì theo plan FE.

## 1. Backend phải làm gì

Một ứng dụng Spring Boot duy nhất, chia module theo nghiệp vụ, phục vụ 3 nhóm người dùng:

| Nhóm | Dùng gì |
|---|---|
| Khách (có hoặc không tài khoản) | Xem thực đơn, đặt bàn (tự xác nhận), giỏ nháp và đặt món trước, vào bàn bằng QR hoặc mã bàn + PIN, gọi món chung, gọi nhân viên, xem hóa đơn, chat AI, đánh giá |
| Nhân viên (`STAFF`, `CHEF`, `MANAGER`, `ADMIN`, vai trò tự tạo) | Sơ đồ bàn, mở và chuyển bàn, gọi món hộ, phục vụ, bếp, thanh toán, đặt bàn, kho, ca làm, báo cáo, phân quyền |
| AI service (`recommender-system`, FastAPI) | BE gọi sang qua mạng nội bộ với `X-Internal-Key`; FE không gọi thẳng |

Quyết định nghiệp vụ đã chốt (plan FE mục 2.9–2.12), BE phải tôn trọng:

1. **Đặt bàn tự xác nhận.** Không có `PENDING`. Server khóa bàn trong transaction, kiểm trùng ±2 giờ, trả 409 nếu vừa có người đặt.
2. **Món chỉ vào bếp khi có phiên bàn** do nhân viên mở. Đặt món trước lưu ở `reservation_items`, không nấu trước.
3. **Thanh toán sau khi ăn**, một lần. Không làm đặt cọc đợt này.
4. **Gộp thu ngân và phục vụ** thành vai trò hệ thống `STAFF`. Chỉ quản lý có `bill:void`.

### 2.1 Vì sao PostgreSQL thay MySQL (spec cũ ghi MySQL)

| Nhu cầu | PostgreSQL giải quyết |
|---|---|
| Chặn đặt trùng bàn | `EXCLUDE USING gist (table_id WITH =, tstzrange(start_at, end_at) WITH &&)` với extension `btree_gist`: CSDL tự chặn hai lượt đặt chồng giờ, kể cả khi code quên kiểm |
| Tìm tên món, tên khách không dấu ("pho" ra "Phở") | Extension `unaccent` + index `pg_trgm` |
| Lưu món gợi ý, ngữ cảnh RAG trong `chat_messages` | Kiểu `jsonb`, truy vấn được |
| Thời điểm | `timestamptz`, không lệch múi giờ |
| Báo cáo | Window function, `date_trunc`, `generate_series` để lấp ngày không có doanh thu |

Thay đổi so với lược đồ spec 6.3 khi đổi sang Postgres:
- `BIGINT AUTO_INCREMENT` → `bigint generated always as identity`.
- `ENUM(...)` → `varchar(20)` + `CHECK (... IN (...))`, map bằng `@Enumerated(EnumType.STRING)`. Thêm giá trị mới chỉ cần sửa CHECK.
- `DATETIME` → `timestamptz` cho thời điểm; `date`, `time` giữ nguyên cho ngày làm, giờ ca.
- `JSON` → `jsonb`. `CHAR(36)` UUID → `uuid`.
- `BOOL` → `boolean`. Tiền `numeric(12,0)` (VND, không dùng số thực).

## 3. Cấu trúc mã nguồn

Chia theo **module nghiệp vụ**, mỗi module tự chứa các lớp của nó (giống "service tách theo nghiệp vụ" của Supply Chain nhưng trong một ứng dụng, không tách microservice).

```
com.restaurant.manager
  RestaurantManagerBeApplication
  config/            SecurityConfig, OpenApiConfig, WebSocketConfig, RedisConfig, JacksonConfig
  common/
    exception/       AppException, GlobalExceptionHandler (ProblemDetail)
    web/             PageResponse, CurrentUser (lấy user từ JWT)
    jpa/             BaseEntity (createdAt, updatedAt qua @CreationTimestamp/@UpdateTimestamp)
  auth/              đăng nhập, refresh, đăng xuất, OTP, JWT
  user/              users, roles, permissions, role_permissions
  customer/          customers, customer_preferences, điểm
  staff/             employees, shifts, employee_schedules
  menu/              categories, items, tags, item_tags, item_options
  floor/             floors, areas, dining_tables, QR
  reservation/       reservations, reservation_tables, reservation_items
  order/             orders, order_items, table_session_members (phiên bàn)
  kitchen/           màn hình bếp
  service/           service_requests, món chờ mang ra
  billing/           bills, vouchers
  inventory/         ingredients, item_ingredients, inventory_transactions
  review/            reviews
  chat/              chat_sessions, chat_messages, gọi AI service
  report/            truy vấn thống kê, xuất CSV
  realtime/          gửi sự kiện STOMP
```

Trong mỗi module:

```
menu/
  MenuController.java        REST, chỉ nhận và trả DTO, gắn @PreAuthorize
  MenuService.java           nghiệp vụ, @Transactional
  ItemRepository.java        Spring Data JPA
  Item.java                  entity
  dto/ItemRequest.java, ItemResponse.java   record + validation
  ItemMapper.java            MapStruct
```

Quy tắc: controller không gọi repository trực tiếp; entity không ra khỏi service; module này chỉ gọi **service** của module khác, không gọi repository của nó.

## 4. Quy ước API (spec mục 8, giữ nguyên)

- Tiền tố `/api/v1`, danh từ số nhiều: `/items`, `/orders/{id}/items`.
- Phân trang `?page=0&size=20&sort=createdAt,desc` → `{content, page, size, totalElements}`.
- Lỗi: **ProblemDetail** `{type, title, status, detail, errors[]}`. 400 dữ liệu sai, 401 chưa đăng nhập, 403 thiếu quyền, 404 không có, 409 xung đột (xóa danh mục còn món, bàn vừa có người đặt), 429 gọi quá nhiều.
- Thời gian ISO-8601 có múi giờ `+07:00`. Tiền là số nguyên VND.
- Endpoint công khai (không token) nằm dưới `/api/v1/public/**` và `/api/v1/auth/**`.

## 5. Bảo mật và phiên (spec mục 5)

| Thành phần | Cách làm |
|---|---|
| Access token | JWT HS256, 15 phút, claim `sub, role, perms, jti, iat, exp`. Ký bằng `NimbusJwtEncoder`, kiểm bằng `NimbusJwtDecoder` |
| Refresh token | Chuỗi ngẫu nhiên 256 bit, cookie `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth`. Redis lưu SHA-256 của nó, TTL 7 hoặc 30 ngày. Xoay vòng mỗi lần refresh, ân hạn 20 giây, dùng lại token cũ thì thu hồi cả family |
| Thu hồi tức thì | Redis `bl:{jti}` (đăng xuất), `user:revoked:{id}`, `role:revoked:{id}` (sửa quyền vai trò). Kiểm trong một `OAuth2TokenValidator` |
| Guest token tại bàn | JWT `role=GUEST_TABLE`, gắn `orderId`, `memberId`; 4 giờ; bị từ chối ngay khi đơn đóng (kiểm khóa Redis `table:order:{tableId}`) |
| Mật khẩu | BCrypt cost 11 |
| Chống dò | Rate limit bằng Redis: đăng nhập 5 lần/15 phút, PIN bàn 5 lần/10 phút, chat 20 câu/phút, tạo đặt bàn theo IP |
| CORS | Chỉ origin của FE (`app.cors.allowed-origins`), cho phép credentials |
| Bí mật | `JWT_SECRET`, `DB_PASSWORD`, `AI_INTERNAL_KEY` lấy từ biến môi trường; hồ sơ `prod` thiếu là không khởi động. Không commit `.env` |
| Upload ảnh | Chỉ jpg, png, webp, tối đa 2 MB, đổi tên file ngẫu nhiên |

## 6. Realtime (STOMP trên `/ws`)

| Topic | Ai nghe | Sự kiện |
|---|---|---|
| `/topic/kitchen` | Bếp | Món mới, món hủy |
| `/topic/tables` | Nhân viên | Trạng thái bàn đổi |
| `/topic/service` | Nhân viên | Yêu cầu của khách, món sẵn sàng cần mang ra, khách báo mở bàn |
| `/topic/orders/{orderId}` | Khách trong phiên bàn | Trạng thái món, thành viên vào, chuyển bàn, đơn đóng |
| `/user/queue/notify` | Từng người | Đã nhận bàn, lượt đặt bị hủy, món sẵn sàng |

Kiểm token ở `CONNECT`, kiểm quyền ở `SUBSCRIBE` bằng `ChannelInterceptor`. Guest token chỉ nghe được `/topic/orders/{orderId của mình}`. Sự kiện gửi **sau khi transaction commit** (`@TransactionalEventListener(phase = AFTER_COMMIT)`) để client không thấy dữ liệu chưa lưu.

## 8. Kiểm thử

### 8.1 Swagger UI (test tay)

- Chạy `./mvnw spring-boot:run`, mở **http://localhost:8080/swagger-ui.html**.
- Endpoint công khai bấm **Try it out** là chạy. Endpoint cần quyền: gọi `POST /api/v1/auth/login` lấy `accessToken`, bấm **Authorize**, dán token (Swagger nhớ token khi tải lại trang, `persist-authorization: true`).
- Mỗi controller có `@Tag` (tên nhóm tiếng Việt), mỗi endpoint có `@Operation(summary)`, DTO có `@Schema(example = ...)` để nút Try it out điền sẵn dữ liệu đúng.
- JSON OpenAPI ở `/v3/api-docs`; FE có thể sinh kiểu hoặc kiểm hợp đồng từ đây.
- Hồ sơ `prod` tắt Swagger trừ khi đặt `SWAGGER_ENABLED=true`.

### 8.2 Test tự động

| Loại | Công cụ | Viết cho |
|---|---|---|
| Unit | JUnit 5 | Tính hóa đơn (phí dịch vụ, chi tối thiểu VIP, voucher, điểm, VAT), kiểm giờ đặt bàn, xoay vòng refresh token, sinh PIN |
| Web slice | `@WebMvcTest` + MockMvc + `spring-security-test` (`jwt().authorities(...)`) | Mỗi controller: 401 không token, 403 thiếu quyền, 400 dữ liệu sai, 200 đúng |
| Tích hợp | `@SpringBootTest` + **Testcontainers** Postgres và Redis | Flyway chạy sạch, luồng chính: đặt bàn trùng trả 409 (hai luồng song song), mở bàn → join QR → gọi món → bếp → thanh toán |
| Realtime | `WebSocketStompClient` trong test tích hợp | Guest không nghe được đơn của bàn khác |

Lệnh: `./mvnw test` (cần Docker đang chạy). Mục tiêu: mọi service nghiệp vụ có test; không merge khi test đỏ.

### 8.3 Dữ liệu demo

Migration `R__demo_seed.sql` (repeatable) chỉ chạy ở hồ sơ dev: 7 vai trò, 34 quyền, 1 tài khoản mỗi vai trò, 3 tầng, khoảng 40 bàn, khoảng 60 món Việt, đơn hàng 60 ngày để có báo cáo và dữ liệu train AI. Ghi rõ trong báo cáo đồ án là dữ liệu giả.

## 10. Quy ước làm việc

- Nhánh: `main` luôn chạy được; mỗi giai đoạn một nhánh `feat/<module>`, gộp qua pull request.
- Commit theo Conventional Commits: `feat(menu): ...`, `fix(auth): ...`.
- Migration đã gộp vào `main` thì **không sửa**, chỉ thêm file mới.
- Không commit bí mật; `.env` nằm trong `.gitignore`.
